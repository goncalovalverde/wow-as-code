# Contributing to wow-as-code

Thank you for your interest in contributing to the Ways of Working as Code specification.

## How to Contribute

### Feedback & Discussion

- **Open an issue** to suggest improvements, report ambiguities in the spec, or propose new features.
- **Start a discussion** for broader topics (e.g., "should we add a new trigger type?").

### Spec Changes

1. Fork the repository.
2. Create a branch: `feat/your-proposal` or `fix/clarification`.
3. Make your changes. Ensure examples stay consistent with the spec.
4. Open a Pull Request with a clear description of *why* the change improves the spec.

### Examples

Contributing new example files is a great way to help:
- Real-world wow/ files (anonymized) from your team
- Examples for industries or team types not yet covered
- Translations of the spec or examples

## Guidelines

- **Keep the spec minimal.** Every addition must justify its complexity.
- **Human-readable first.** If it can't be understood in a plain text editor, it doesn't belong.
- **Agent-friendly always.** Consider how agents will parse and use any new feature.
- **Backward compatible.** Breaking changes require a major version bump and migration path.

## Code of Conduct

Be respectful, constructive, and assume good intent. We're building something new together.
